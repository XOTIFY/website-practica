Moștenirea Simplă
în C#

O explicație clară și omenească a unui concept esențial din Programarea Orientată pe Obiecte

Ce este moștenirea, de fapt?

Înainte să vorbim de cod, gândește-te la viața reală. Orice animal mănâncă, doarme și respiră. Dacă vorbim acum despre un câine specific, el face toate astea — plus că latră și poate fi dresat.

În programare, moștenirea funcționează exact la fel: o clasă „copil" preia automat tot ce are clasa „părinte", fără să rescrii nimic. Câinele moștenește comportamentele de bază ale oricărui animal.

Definiție: Moștenirea simplă înseamnă că o clasă derivată (copil) preia proprietățile și metodele unei singure clase de bază (părinte). În C# se exprimă cu : — de exemplu class Caine : Animal.

Schema vizuală

Moștenirea simplă este o relație de la unu la unu — un copil, un singur părinte:

Animal ← clasa de bază (părinte)
↓
Caine ← clasa derivată (copil)

Sau un lanț mai lung — B moștenește din A, C moștenește din B:

Vehicul ← baza
↓
Masina ← moștenește din Vehicul
↓
MasinaSport ← moștenește din Masina

Sintaxa în C# — pas cu pas

1. Clasa de bază

Definim clasa Animal cu proprietăți și metode comune tuturor animalelor. Metoda marcată cu virtual poate fi rescrisă de copii:

class Animal
{
    public string Nume;
    public int    Varsta;

    public void Mananca()
    {
        Console.WriteLine(Nume + " mănâncă.");
    }

    public virtual void Sunet() // virtual = poate fi rescris
    {
        Console.WriteLine("Sunet generic de animal.");
    }
}

2. Clasa derivată (copilul)

Caine moștenește din Animal cu :, rescrie Sunet() cu override și adaugă propriile metode:

class Caine : Animal  // ":" înseamnă "moștenește din"
{
    public string Rasa;  // propriu doar câinelui

    public override void Sunet()  // rescrie metoda din Animal
    {
        Console.WriteLine(Nume + " face: Ham Ham!");
    }

    public void AduceMingea()  // metodă nouă, nu există în Animal
    {
        Console.WriteLine(Nume + " aduce mingea!");
    }
}

Câinele a moștenit Nume, Varsta și Mananca() fără să le rescrie, a rescris Sunet() și a adăugat AduceMingea().

3. Utilizarea în Main

class Program
{
    static void Main()
    {
        Caine c = new Caine();
        c.Nume   = "Rex";        // moștenit din Animal
        c.Varsta = 3;           // moștenit din Animal
        c.Rasa   = "Labrador";  // propriu câinelui

        c.Mananca();       // Rex mănâncă.       (din Animal)
        c.Sunet();         // Rex face: Ham Ham! (rescris)
        c.AduceMingea();   // Rex aduce mingea!  (propriu)
    }
}

Cuvintele cheie esențiale

virtual și override

virtual în clasa de bază înseamnă „această metodă poate fi rescrisă de copii". override în clasa derivată înseamnă „rescriu această metodă cu comportamentul meu". Dacă uiți virtual, compilatorul refuză override.

base — apelarea părintelui

Uneori vrei să extinzi comportamentul părintelui, nu să îl înlocuiești complet. Folosești base:

public override void Sunet()
{
    base.Sunet();  // mai întâi apelăm metoda din Animal
    Console.WriteLine(Nume + " mai latră o dată.");
}

Constructori și base()

Dacă clasa de bază are constructor cu parametri, copilul îl apelează cu base():

class Animal
{
    public string Nume;
    public Animal(string nume) { Nume = nume; }
}

class Caine : Animal
{
    public string Rasa;
    public Caine(string nume, string rasa)
        : base(nume)  // trimite "nume" la constructorul Animal
    {
        Rasa = rasa;
    }
}

Polimorfismul — puterea moștenirii

Cel mai frumos lucru la moștenire: poți trata un obiect de tip copil ca și cum ar fi de tipul părintelui. C# știe la execuție ce metodă să apeleze:

Animal a = new Caine();  // Caine tratat ca Animal
a.Sunet();
// Va afișa "Rex face: Ham Ham!" — nu sunetul generic!
// C# știe că obiectul real este Caine.

Exemplu practic: Poți crea o listă de Animal care conține câini, pisici și păsări amestecate și să apelezi Sunet() pe fiecare — fiecare va face sunetul lui propriu, automat.

Exemplu complet — Vehicul și Masina

using System;

class Vehicul
{
    public string Marca;
    public int    AnFabricatie;

    public Vehicul(string marca, int an)
    {
        Marca = marca;
        AnFabricatie = an;
    }

    public virtual void Descrie()
    {
        Console.WriteLine("Vehicul: " + Marca +
                          " (" + AnFabricatie + ")");
    }
}

class Masina : Vehicul
{
    public int NrUsi;

    public Masina(string marca, int an, int usi)
        : base(marca, an)
    {
        NrUsi = usi;
    }

    public override void Descrie()
    {
        base.Descrie();
        Console.WriteLine("  Mașină cu " + NrUsi + " uși.");
    }
}

class Program
{
    static void Main()
    {
        Masina m = new Masina("Dacia", 2022, 4);
        m.Descrie();
        // Output:
        // Vehicul: Dacia (2022)
        //   Mașină cu 4 uși.
    }
}

Avantaje și dezavantaje

Avantaje

  • Elimină codul duplicat
  • Ușor de extins cu clase noi
  • Polimorfism — cod flexibil
  • Logica comună într-un singur loc
  • Mai ușor de întreținut

Dezavantaje

  • Cuplare strânsă între clase
  • Modificarea părintelui afectează toți copiii
  • Ierarhii adânci greu de urmărit
  • C# nu permite moștenire din mai mulți părinți

Concluzii

Moștenirea simplă este poate cel mai important concept din POO. Odată înțeles, îl vei vedea peste tot — în framework-uri, în aplicații mari, peste tot.

Cel mai important de reținut: moștenirea nu înseamnă copiere de cod, ci o relație structurată în care copilul este un tip de părinte, extinzând sau personalizând comportamentul acestuia.

Am aplicat acest concept în cadrul practicii în proiectele POO, unde clasele de date puteau fi organizate ierarhic pentru a evita repetarea codului comun.
